# 校验与超时规则（validation.md）

> 目的：四端**在提交前**用同一套规则拦住明显错误，避免把用户送进一次注定的失败请求。
> 服务端永远是最终裁判；客户端校验只做「提前拦住」，不能放宽服务端限制。
> 版本：contracts 1.0.0。

## 1. 账号与注册

| 字段 | 规则 | 与服务端一致 |
|---|---|---|
| 用户名（注册） | 长度 3–32；`^[A-Za-z0-9][A-Za-z0-9_.-]*$`；**不能是邮箱**（不含 `@`） | `sso/app/security.py: validate_username` |
| 密码 | 8–64 字符；UTF-8 ≤72 字节；必须同时含字母与数字；不得是常见弱口令 | `validate_password` |
| 邮箱 | 必填；≤254；`^[^@\s]+@[^@\s]+\.[^@\s]+$`；服务端归一为小写 | `validate_email` |
| 登录标识 | 用户名**或**邮箱；只做 trim，不在这里猜格式 | `sso/app/authentication.py` |

客户端实现要点：

- 注册表单的标识字段文案必须是「用户名」，并在下方另起一行说明「只能用用户名，不能填邮箱」。
- 密码强度提示只在**输入过程中**给规则，不在失焦时报错；提交后由服务端错误码决定文案。
- 邮箱只做「有 `@` 和 `.`」级别的前置检查，不要自己实现 RFC 5322。
- 服务端对未知字段不报错（`LoginRequest`/`RegisterRequest` 未 `extra="forbid"`），
  但客户端仍只发契约里的字段。

## 2. 个人资料

| 字段 | 规则 | 备注 |
|---|---|---|
| 昵称 | trim + NFC 后 **1–32 个码点**；不能为空；不能含 Unicode 类别 `C*`（控制/格式/代理/私用/未分配） | 服务端按 `len()` 数码点，客户端必须按 **rune/码点** 而不是 UTF-16 单元计数 |
| 简介 | 纯文本；NFC；`\r\n`/`\r` 归一为 `\n`；trim 后 ≤**500** 字符；空串等价于清空（服务端存 `null`） | 允许 `\n`，其余控制字符拒绝 |
| 昵称默认值 | 没有昵称时展示与编辑都用 SSO 用户名兜底 | 「保存」只在昵称合法时可用，不做提交后提示 |

客户端实现要点：

- 保存是**全量**（`PUT`），不是 PATCH：未改动的字段也要一起发。
- `additionalProperties: false`：不要顺手加字段（例如 `display_name`），服务端会 400。
- 校验函数必须与「何时允许点保存」是同一个判据，不要写两份。

## 3. MC 白名单

| 字段 | 规则 | 备注 |
|---|---|---|
| 名字 | `^[A-Za-z0-9_]{3,16}$` | 服务端归一为**小写**后存储；展示用 `name_display`（原始写法） |
| 备注 | 1–200 字符；不能含控制字符（`ord < 32` 或 `== 127`）；必填 | 空白串按 1 字符算合法，但客户端应 trim 后要求非空 |

客户端实现要点：

- 名额：`quota.limit / used / remaining`；`remaining == 0` 时添加按钮禁用并提示「先撤回一个」。
- 幂等：重复提交同一个名字（大小写不敏感）是成功（200 + 已有条目），不要报错。
- 撤回：别人的条目一律 404 `not_found`；已撤回的再撤一次是幂等成功。
- `uuid` 恒为 `null`，不要展示、不要当判定依据；`rcon.endpoint` 不进界面。
- 错误文案不能出现名字以外的技术细节：`name_taken` 的界面文案不暴露「谁占用的」。

## 4. 图片

| 项 | 头像 `avatar` | 头图 `banner` |
|---|---|---|
| 上传大小上限 | **5 MB** | **10 MB** |
| 输出最大边长 | **512 px** | **1600 px** |
| 宽高比 | 1:1（裁切框） | **5:1**（裁切框） |
| 上传格式 | PNG / JPEG / WebP | PNG / JPEG / WebP |
| 输出格式 | **PNG**（统一重编码） | **PNG**（统一重编码） |

上传前流程（顺序不能换）：

```text
选图 → 解码 → 按平台惯例裁切（1:1 / 5:1）→ 缩放到上限内 → 重编码 PNG(去元数据)
     → PUT /userinfo/v1/profile/{kind}（multipart，字段名 file，Content-Type: image/png）
```

规则：

- 客户端**不直连** file 服务，也不落盘图片字节；位图按 `sha256` 缓存。
- 声明类型必须与内容一致：服务端会嗅探文件头，改扩展名会被 400 `unsupported_image_type`。
- 413 `image_too_large` 说明超过服务端上限（客户端换算 MB 用 1024 进制，与 5 MB/10 MB 对齐）。
- 409 `image_quota_exceeded`：提示先删旧图，不要自动删除用户的其他图片。
- 保存顺序：**图片先、文字后**。部分成功时刷新服务端快照，只提交已成功的那部分；取消则丢弃所有未保存预览。
- 读取接口支持 `ETag`（sha256）与 `If-None-Match`：命中返回 304，不要再解码。

## 5. 超时

| 场景 | 超时 | 来源 |
|---|---|---|
| 普通请求（列表、详情、登录、注册） | **20 秒** | `EliCloudGateway` / SDK 默认 |
| 服务探活（`GET /mc/healthz`） | **8 秒** | `EliCloudGateway.ProbeTimeout` |
| 资料保存（`PUT /userinfo/v1/profile`） | **30 秒** | `EliCloudGateway.UpdateMyProfileAsync` |
| 图片上传（`PUT /userinfo/v1/profile/{kind}`） | **60 秒** | `EliCloudGateway.UploadMyImageAsync` |

客户端实现要点：

- 超时是**单次请求**的上限，不是「用户可感知的最长等待」；UI 可在 1–2 秒后显示进行中状态。
- 超时后**不要自动重试写操作**（注册、保存、上传、撤回）；读操作最多重试一次。
- 取消（页面关闭、用户点取消）必须传取消令牌，不能把取消当成失败提示。

## 6. 探活

| 服务 | 端点 | 解析规则 |
|---|---|---|
| `mc` | `GET /mc/healthz` | **200 与 503 都解析 body**；只有其它状态码才算失败 |
| 其它 | — | 当前无探活端点：用清单里的声明状态，不要判成「不可用」 |

- 可用性判据：`mc` → `rcon.reachable == true`。服务在跑但 RCON 挂了，对用户就是「加不了名字」。
- 探活失败**不得**把用户踢出当前页面；当前路由的服务被**确认**不可用时才 `Replace(Home)`。
- 探活结果里的技术字段（`endpoint`、`error`、`version`）不能原样进界面。

## 7. 明确不做

- 不做本地账号缓存、不做「记住我」、不做离线模式：凭据只在内存。
- 不在客户端复刻服务端的限流窗口（只消费 `Retry-After`）。
- 不校验 JWT 签名（业务服务的职责）；客户端只读 `sub`/`scope` 用于展示与自检。
- 不因为一次 403 `insufficient_scope` 就清空会话：先提示重新登录，由用户触发。
